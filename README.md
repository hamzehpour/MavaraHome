# خانه ماورا — راهنمای تست (فاز ۴ تا ۸)

این فایل را از اول تا آخر بخوانید — نوشته شده که بدون دانش برنامه‌نویسی هم بتوانید
پروژه را روی کامپیوتر خودتان با ویژوال استودیو کد بالا بیاورید و تست کنید.

---

## بخش ۱ — چیزهایی که باید نصب کنید (فقط یک‌بار)

۱. **Python نسخه ۳.۱۱ یا بالاتر** — از [python.org/downloads](https://www.python.org/downloads/)
   دانلود کنید. هنگام نصب روی ویندوز، تیک **Add Python to PATH** را حتماً بزنید.
2. **Visual Studio Code** — از [code.visualstudio.com](https://code.visualstudio.com/)
3. در VS Code، از قسمت Extensions (آیکون مربع‌های کنار هم در نوار کناری چپ)، اکستنشن
   **Python** (ساخته‌ی Microsoft) را نصب کنید.

چیز دیگری لازم نیست نصب کنید — این پروژه از کتابخانه‌های آماده‌ی خیلی سنگین (مثل
Node.js یا Docker) استفاده نمی‌کند تا نصب و تست برایتان ساده بماند.

> نکته درباره‌ی ربات تلگرام: برای تست **خودِ ربات** (نه سایت) به یک BOT_TOKEN واقعی
> از [@BotFather](https://t.me/BotFather) در تلگرام نیاز دارید. برای تست کامل **سایت**
> این توکن لازم نیست — پایین‌تر توضیح داده شده.

---

## بخش ۲ — باز کردن پروژه در VS Code

1. فایل zip را در یک پوشه (مثلاً `Documents\MavaraHome`) اکسترکت کنید. باید دو پوشه ببینید:
   - `bot/` — ربات تلگرام + بک‌اند مشترک (API)
   - `website/` — سایت
2. در VS Code: `File → Open Folder…` و پوشه‌ی `bot/` را باز کنید (این پوشه‌ی اصلی کار
   شماست — بک‌اند سایت هم همین‌جاست).
3. یک ترمینال داخل VS Code باز کنید: منوی بالا → `Terminal → New Terminal`.

## بخش ۳ — نصب و راه‌اندازی اولیه (در ترمینال VS Code)

```bash
# ۱) نصب کتابخانه‌های لازم
pip install -r requirements.txt

# اگر روی مک/لینوکس بودید و pip کار نکرد، این را امتحان کنید:
# pip3 install -r requirements.txt
```

```bash
# ۲) ساخت فایل تنظیمات
# ویندوز (PowerShell):
copy .env.example .env
# مک/لینوکس:
cp .env.example .env
```

فایل `.env` را در VS Code باز کنید (روی آن دابل‌کلیک کنید) و این دو خط را عوض کنید:

```
ENV=test
JWT_SECRET=یک-رشته-تصادفی-طولانی-اینجا
```

برای ساخت یک `JWT_SECRET` تصادفی، در همان ترمینال بزنید:

```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

خروجی را کپی کنید و جای `یک-رشته-تصادفی-طولانی-اینجا` بگذارید. (اگر روی ویندوز `python3`
کار نکرد، `python` را امتحان کنید.)

`BOT_TOKEN` را فعلاً دست نزنید (مقدار `dummy` هم برای تست سایت کافی است — فقط برای
تست خود ربات تلگرام لازم است یک توکن واقعی از BotFather بگذارید).

```bash
# ۳) ساخت دیتابیس
python3 migrate.py
```

```bash
# ۴) پر کردن دیتابیس با داده‌ی تستی عمومی (رویداد، رزرو، ادمین تلگرامی و ...)
python3 seed_database.py
python3 seed_portfolio.py
```

```bash
# ۵) پر کردن دیتابیس با سناریوهای تست فاز ۴ تا ۸ — این اسکریپت را خودم برای همین
#    منظور نوشتم: یک حساب ادمین سایت، دو شماره مشتری (یکی وصل به تلگرام، یکی نه)،
#    ۵ عضو تیم، یک بلیت تأییدشده‌ی آماده، یک مکالمه‌ی نمونه، و یک کد OTP واقعی که
#    همان لحظه چاپ می‌شود — همه چیزهایی که برای تست لازم دارید، بدون این‌که خودتان
#    مجبور باشید دستی چیزی بسازید.
python3 seed_phase4_8.py
```

خروجی این دستور آخر را **حتماً نگه دارید** (اسکرول بالا بروید یا از ترمینال کپی کنید)؛
شماره‌تلفن‌ها، رمز ادمین، و کد OTP واقعی که همین الان برایتان ساخته شده، همان‌جا چاپ
می‌شود.

```bash
# ۶) بررسی سلامت پروژه — باید بیشتر موارد ✅ باشد
python3 health_check.py
```

دو مورد ممکن است ❌ بمانند: «owner/admin تنظیم نشده» و «کارت بانکی تنظیم نشده» — این دو
فقط هشدارِ تنظیمات هستند (نه باگ)، چون هنوز شماره تلگرام واقعی خودتان را به عنوان ادمین
تنظیم نکرده‌اید. برای رفع کامل‌شان، `BOOTSTRAP_ADMIN_IDS` را در `.env` با آیدی عددی
تلگرام خودتان پر کنید (با ربات @userinfobot در تلگرام آیدی عددی خودتان را پیدا کنید)،
یا از پنل ادمین یک کارت بانکی ثبت کنید — هیچ‌کدام برای تست سایت ضروری نیستند.

## بخش ۴ — روشن کردن سایت + بک‌اند (یک دستور، یک ترمینال)

این پروژه سایت و API را روی **یک پورت مشترک** اجرا می‌کند تا نیازی به دو سرور جدا نباشد:

```bash
# ویندوز (PowerShell):
$env:STATIC_ROOT="..\website"; python3 -m api.server
# مک/لینوکس:
STATIC_ROOT=../website python3 -m api.server
```

اگر پیام `Mavara unified API listening on :8788` را دیدید، یعنی کار کرد. مرورگر را باز
کنید و به این آدرس بروید:

```
http://127.0.0.1:8788/
```

این را باز بگذارید (پنجره‌ی ترمینال را نبندید) — تا وقتی تست می‌کنید باید روشن بماند.
برای خاموش کردن، در ترمینال `Ctrl+C` بزنید.

## بخش ۵ — چک‌لیست تست، فاز به فاز

با داده‌ی چاپ‌شده از `seed_phase4_8.py` این‌ها را امتحان کنید:

### فاز ۴ — حساب کاربری مشتری (ورود با کد از طریق تلگرام)
1. به `http://127.0.0.1:8788/pages/account.html` بروید.
2. شماره‌ی «مشتری با تلگرام وصل» را که اسکریپت چاپ کرد (مثلاً `09120000001`) وارد کنید
   و «ارسال کد ورود» را بزنید.
3. کد ۶ رقمی که همان لحظه در ترمینال چاپ شده بود را وارد کنید. باید وارد داشبورد
   حساب‌تان شوید و رزرو تستی را ببینید.
4. برای تست مسیر دوم: شماره‌ی «مشتری بدون تلگرام» را امتحان کنید — باید صفحه‌ی
   «اتصال به تلگرام» را ببینید (چون این پروژه سرویس پیامک ندارد و کد فقط از طریق
   ربات تلگرام ارسال می‌شود — این یک تصمیم آگاهانه بود، نه محدودیت فراموش‌شده).
   تکمیل این مسیر نیاز به یک ربات تلگرام واقعی در حال اجرا دارد (بخش ۷).

### فاز ۵ — پیام‌رسانی
1. در همان داشبورد حساب کاربری، پایین صفحه بخش «پیام به پشتیبانی» را ببینید — یک
   مکالمه‌ی نمونه از قبل آنجاست.
2. یک پیام جدید بفرستید.
3. در پنل ادمین (بخش ۶) به `messages.html` بروید و پاسخ بدهید — پیام باید در همان
   لحظه (با رفرش خودکار هر ۱۵ ثانیه) در داشبورد مشتری هم دیده شود.

### فاز ۶ — بلیت PDF و پذیرش درِ ورودی
1. در داشبورد حساب مشتری، روی «دانلود بلیت PDF» برای رزرو تستی کلیک کنید — باید یک
   PDF با QR واقعی باز شود.
2. خط «Signed check-in payload» که `seed_phase4_8.py` چاپ کرد (شبیه
   `MV-XXXXXX.abcdef123456`) را عیناً کپی کنید.
3. در پنل ادمین به `checkin.html` بروید، این مقدار را وارد کنید، «بررسی» را بزنید، سپس
   «تأیید ورود» — باید پیام موفقیت ببینید. اگر دوباره همان مقدار را بزنید، باید بگوید
   «قبلاً وارد شده».

### فاز جدید (خواسته‌ی شما) — اعضای خانه ماورا
1. به `http://127.0.0.1:8788/pages/team.html` بروید — باید ۵ عضو تستی را ببینید.
2. روی یکی کلیک کنید — باید صفحه‌ی رزومه‌ی شخصی او باز شود.
3. در پنل ادمین به `team.html` بروید — می‌توانید عضو جدید اضافه/ویرایش/حذف کنید،
   عکس پروفایل آپلود کنید.

## بخش ۶ — تست پنل ادمین

1. به `http://127.0.0.1:8788/pages/admin/login.html` بروید.
2. نام‌کاربری/رمزی که `seed_phase4_8.py` چاپ کرد را وارد کنید (پیش‌فرض: `admin` /
   `MavaraTest123!` — پیشنهاد می‌شود بعداً از پنل یا `create_web_admin.py` یک حساب
   واقعی با رمز خودتان بسازید).
3. از منوی کناری همه‌چیز در دسترس است: داشبورد، رویدادها، تقویم و سانس، رزروها،
   رزومه، **اعضای خانه ماورا**، **پیام‌ها**، **پذیرش بلیت**.

## بخش ۷ — تست خودِ ربات تلگرام (اختیاری، نیاز به توکن واقعی)

اگر می‌خواهید تجربه‌ی کامل (شامل دریافت کد OTP واقعی در چت تلگرام، نه فقط از ترمینال)
را ببینید:

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام دهید، `/newbot` بزنید، و
   توکنی که می‌دهد را در `.env` جای `BOT_TOKEN=dummy` بگذارید.
2. آیدی عددی تلگرام خودتان را با [@userinfobot](https://t.me/userinfobot) پیدا کنید
   و در `.env` در `BOOTSTRAP_ADMIN_IDS` بگذارید.
3. یک ترمینال **دوم** در VS Code باز کنید (کنار ترمینال سایت، نه به‌جایش) و بزنید:
   ```bash
   python3 bot.py
   ```
4. حالا در تلگرام به ربات‌تان `/start` بزنید — باید منوی خوش‌آمدگویی را ببینید.
5. اگر روی سایت (`account.html`) با شماره‌ی خودتان («مشتری بدون تلگرام») وارد شوید،
   دکمه‌ی «اتصال به تلگرام» شما را مستقیم به همین ربات با یک لینک یک‌بارمصرف می‌برد —
   بعد از زدن Start، به سایت برگردید و دوباره «ارسال کد ورود» را بزنید: این‌بار کد
   واقعاً در همان چت تلگرام برایتان می‌آید.

### باگ‌های واقعی که در همین کار پیدا و رفع شدند (نه چیزی که خودم اضافه کرده باشم قبلاً)
این‌ها چیزهایی هستند که **از قبل در پروژه‌ی فاز ۱-۳ بودند** و من در همین بررسی پیدا کردم؛
شفاف گزارش می‌دهم چون خودتان گفتید بخواهید بدانید:

1. **باگ ناوبری در هدر سایت** — کلیک روی لوگو یا منوی بالای سایت از داخل هر صفحه‌ای
   غیر از صفحه‌ی اصلی (یعنی تقریباً همه‌ی صفحات)، به آدرس اشتباه می‌رفت (۴۰۴ می‌داد).
   فوتر سایت این مشکل را نداشت چون یک الگوی درست‌تر داشت. رفع شد.
2. **باگ در تأیید رزرو از سایت** — دکمه‌ی «تأیید» روی یک رزرو در پنل ادمین، اگر بات
   تلگرام (aiogram) نصب نبود، کرش می‌کرد — یعنی این دکمه‌ی وب به‌طور غیرمنتظره وابسته
   به یک کتابخانه‌ی مخصوص تلگرام بود، برخلاف اصل خود پروژه («بک‌اند وب نباید وابسته به
   تلگرام باشد»). رفع شد.
3. **یک باگ امنیتی که خودم در حین ساخت فاز ۴ ایجاد کردم و با تست خودم پیدا کردم** —
   برای مدت کوتاهی، توکن ورود مشتری روی endpointهای مخصوص ادمین هم قبول می‌شد. قبل از
   تحویل، با تست مستقیم پیدا و رفع و دوباره تست شد (جزئیات کامل در `CHANGELOG.md`).

### مواردی که عمداً ناقص ماندند — با دلیل فنی
| مورد | چرا الان کامل نشد |
|---|---|
| اسکن دوربین برای پذیرش بلیت (به‌جای وارد کردن دستی کد) | نیاز به یک کتابخانه‌ی جاوااسکریپت خواندن QR از طریق `getUserMedia` دارد که باید روی مرورگر واقعی موبایل تست شود؛ محیط توسعه‌ی من مرورگر واقعی ندارد. نسخه‌ی دستی کاملاً کار می‌کند و برای شروع کافی است — افزودن دوربین یک تغییر کوچک و مجزا در آینده است. |

## بخش ۹ — چیزهایی که فقط شما (روی سرور واقعی‌تان) می‌توانید تأیید کنید

اینها را از قبل، صادقانه، در سند اصلی پروژه هم گفته بودند و همچنان صادق است — نه چیزی
که من مخفی کرده باشم:

- ارسال واقعی پیام در تلگرام (کد OTP، اعلان پیام پشتیبانی) — نیاز به `aiogram` نصب‌شده
  و یک بات واقعی در حال اجرا دارد (بخش ۷ بالا).
- تولید واقعی تصویر QR — نیاز به پکیج `qrcode` دارد (در `requirements.txt` هست، فقط
  در سندباکس من قابل نصب نبود چون اینترنت ندارم).
- تست روی مرورگر واقعی موبایل (کیبورد فارسی، اندازه‌ی صفحه، لمس).

## بخش ۱۰ — یادآوری از بررسی اولیه (چیزی که تغییرش ندادم، چون خودتان باید تصمیم بگیرید)

در همان اولین پیام این مکالمه گفته بودم: داخل پوشه‌ی `website/` یک پوشه‌ی `backend/`
(کد Node.js قدیمی، از قبل از یکپارچه‌سازی فاز ۱) و یک `README.md` قدیمی (که معماری
منسوخ را توضیح می‌دهد) هنوز وجود دارند — هیچ‌کدام دیگر استفاده نمی‌شوند (سایت واقعی از
`api/server.py` پایتون استفاده می‌کند، نه از این Node). طبق دستور صریح خودتان («هرگز
کد بی‌ربط را ریفکتور/حذف نکن مگر لازم باشد»، «قبل از تغییرات بزرگ توضیح بده و تأیید
بگیر»)، این دو را دست‌نخورده نگه داشتم و فقط اینجا دوباره یادآوری می‌کنم. اگر می‌خواهید
حذف یا آرشیو شوند تا در آینده کسی (یا یک هوش مصنوعی دیگر) گمراه نشود، فقط بگویید تا
انجام بدهم — یک تغییر کوچک و کم‌ریسک است (فقط حذف دو مورد، بدون اثر روی چیز دیگری).
