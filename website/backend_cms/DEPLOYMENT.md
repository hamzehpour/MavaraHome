# استقرار روی هاست اشتراکی (سی‌پنل یا دایرکت‌ادمین)

این راهنما فرض می‌کند دسترسی SSH ندارید — فقط پنل گرافیکی (سی‌پنل یا
دایرکت‌ادمین). اگر SSH دارید (مثلاً پکیج «پایتون» ایران‌سرور — همه‌ی
تیرهای این پکیج SSH می‌دهند)، همین مراحل را دنبال کنید، فقط جای اجرای
مرحله‌ی ۳ و ۵ از دکمه‌های پنل، همان دستورات را مستقیم در ترمینال SSH
بزنید (سریع‌تر است، نتیجه یکی‌ست). مرحله‌ی ۲ («Setup Python App») را
همچنان از پنل انجام دهید — این بخشیه که دامنه را به اپ پایتون وصل
می‌کند (Passenger)، با SSH جایگزین نمی‌شود.

> **برای اجرای دستورات از طریق SSH به‌جای ترمینال مجازی پنل:** بعد از
> ساخت اپ در مرحله‌ی ۲، وارد SSH شوید و محیط مجازی همان اپ را فعال
> کنید (مسیر دقیق را پنل بعد از ساخت اپ نشان می‌دهد، معمولاً چیزی شبیه):
> ```bash
> source ~/virtualenv/backend_cms/3.9/bin/activate
> cd ~/public_html/backend_cms
> pip install -r requirements.txt
> python3 create_admin.py
> ```

## پیش‌نیاز

مطمئن شوید پنل هاست شما امکان **«Setup Python App»** (سی‌پنل) یا معادلش در
دایرکت‌ادمین را دارد. خیلی از هاست‌های اشتراکی ارزان فقط PHP دارند — اگر این
گزینه را در پنل خود پیدا نکردید، این روش برای هاست شما جواب نمی‌دهد (باید یا
هاست را عوض کنید، یا سراغ یک VPS واقعی بروید).

## ساختار نهایی روی سرور

```
public_html/                    ← ریشه‌ی دامنه شما
├── index.html, pages/, assets/  ← فایل‌های استاتیک سایت (همین website/)
├── media/                       ← عکس‌ها/ویدیوهای آپلودی — پوشه‌ی معمولی،
│                                   مستقیم توسط وب‌سرور سرو می‌شود
└── backend_cms/                 ← این پوشه — اپ پایتون (از طریق پنل مونت می‌شود)
```

## مرحله ۱ — آپلود فایل‌ها

با File Manager یا FTP، کل پوشه‌ی `website/` (شامل `backend_cms/` و `media/`)
را در `public_html` آپلود کنید — دقیقاً با همین ساختار.

## مرحله ۲ — ساخت اپ پایتون در پنل

**سی‌پنل («Setup Python App»):**
1. «Create Application» را بزنید.
2. Python version: هرچه جدیدتر بهتر (۳.۹ به بالا).
3. Application root: مسیر `backend_cms` (نسبت به ریشه‌ی هاست شما — مثلاً
   `public_html/backend_cms` یا هرجایی که آپلود کردید).
4. Application URL: دامنه‌ی خودتان را انتخاب کنید، مسیر (URL) را `/api`
   بگذارید (یا هرچیز دیگری — کد این پروژه با هر دوی این حالت‌ها که پنل مسیر
   را از URL حذف کند یا نکند کار می‌کند، برای همین دو بار روی مسیر ثبت شده).
5. Application startup file: `passenger_wsgi.py`
6. Application Entry point: `application`
7. «Create» را بزنید.

**دایرکت‌ادمین:** مراحل مشابه، از بخش Python App (اگر موجود بود) — همان چهار
مورد بالا (مسیر پوشه، دامنه/مسیر URL، فایل startup، متغیر application) را پر
کنید.

## مرحله ۳ — نصب وابستگی‌ها

پنل معمولاً یک دکمه یا فیلد «Run Pip Install» دارد؛ فایل `requirements.txt`
همین پوشه را انتخاب کنید (یا دستی: `pip install -r requirements.txt` از همان
ترمینال مجازی که پنل برای این اپ می‌سازد).

## مرحله ۴ — متغیرهای محیطی

پنل یک بخش «Environment Variables» دارد. این‌ها را آنجا اضافه کنید (نه در یک
فایل `.env` — چون خیلی از پنل‌ها این فایل را نمی‌خوانند، مطمئن‌ترین راه همین
تنظیمات خودِ پنل است):

```
JWT_SECRET=<یک رشته‌ی تصادفی طولانی>
```

برای ساخت مقدار `JWT_SECRET`، از «Run Pip Install»/ترمینال مجازی پنل بزنید:
```bash
python3 -c "import secrets; print(secrets.token_hex(32))"
```

اگر مسیر `media/` شما جای دیگری غیر از کنار `backend_cms/` است، متغیر زیر را
هم اضافه کنید (مسیر کامل، نه نسبی):
```
MEDIA_ROOT=/home/yourcpaneluser/public_html/media
```

بعد از اضافه‌کردن متغیرها، اپ را «Restart» کنید (دکمه‌اش در همان صفحه‌ی پنل
است).

## مرحله ۵ — ساخت حساب ادمین اول

از همان ترمینال مجازی که پنل برای این اپ پایتون فراهم می‌کند (نه SSH معمولی —
سی‌پنل این را زیر همان صفحه‌ی Setup Python App با یک دکمه «Enter to the virtual
environment» می‌دهد):

```bash
python3 create_admin.py
```

نام کاربری و رمز عبور (حداقل ۱۰ کاراکتر) را وارد کنید — همین‌ها را در
`pages/admin/login.html` سایت استفاده خواهید کرد.

## مرحله ۶ — تست

```
https://yourdomain.com/api/v1/events
```
باید یک JSON خالی (`{"data":[]}`) برگرداند. اگر همین را دیدید، بک‌اند آماده
است — به `https://yourdomain.com/pages/admin/login.html` بروید و با حساب
مرحله‌ی ۵ وارد شوید.

## نکته‌ی مهم: `media/` باید مستقیم قابل‌دسترس باشد

آپلود عکس/پوستر از پنل ادمین، فایل را داخل `media/<نوع>/...` می‌نویسد. این
پوشه باید **مستقیم توسط وب‌سرور** (نه از طریق اپ پایتون) سرو شود — یعنی همان
پوشه‌ی معمولی کنار `index.html` باشد، دقیقاً همان‌طور که در «ساختار نهایی»
بالا نشان داده شده. اگر آدرس یک عکس آپلودشده (مثلاً
`https://yourdomain.com/media/poster/xxx.jpg`) باز نشد، یعنی این پوشه جای
درستی نیست یا دسترسی خواندن (permission) ندارد.

## این بک‌اند فقط محتوا را مدیریت می‌کند

رزرو، بلیت، پرداخت — هیچ‌کدام اینجا نیست. دکمه‌ی «رزرو» روی هر رویداد فقط یک
لینک تلگرام/تلفن است (از همان فیلدهایی که در فرم رویداد پر می‌کنید). رزرو
واقعی کاملاً از طریق ربات تلگرام (پوشه‌ی `bot/` در ریشه‌ی این ریپو) انجام
می‌شود — یک پروژه‌ی کاملاً جدا، با هاست جداگانه (نیاز به SSH/سرور واقعی دارد،
چون یک پروسه‌ی همیشه‌روشن است) — به `bot/README.md` مراجعه کنید.
