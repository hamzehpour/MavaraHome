# ۰۵ — فرانت‌اند و سیستم طراحی

این سند هم برای توسعه‌دهنده است و هم برای **طراح محصول**. بخش «سیستم طراحی»
و «مدل محتوا» را حتی اگر کد نمی‌نویسی بخوان.

## قاعده‌ی بنیادی: بدون build

نه npm، نه bundler، نه فریمورک، نه TypeScript. فایل‌ها همان‌طور که نوشته
می‌شوند سرو می‌شوند. دیپلوی یعنی کپی کردن.

**پیامدهایی که باید بدانی:**
- ترتیب `<script>`ها معنادار است: `app.js` قبل از `site.js` (و `resume.js`
  بعد از هر دو، در صفحاتی که رزومه دارند).
- حالت مشترک با متغیرها و توابع سراسری اداره می‌شود.
- بعد از هر دیپلوی، کش مرورگر باید رد شود (`Ctrl+Shift+R`).

**قرارداد «فهرست ← صفحه‌ی ویرایش»:** ساخت/ویرایش موجودیت‌های بزرگ در یک
**صفحه‌ی مستقل** انجام می‌شود، نه مودال. مودال فقط برای فرم‌های کوچک است.
دلیلش تجربه‌ی واقعی بود: فرم رویداد آن‌قدر بزرگ شد که داخل مودال دو اسکرول
تودرتو می‌خورد.

## لایه‌ی جاوااسکریپت

| فایل | مسئولیت |
|---|---|
| `app.js` | **لایه‌ی داده.** `MAVARA_API_BASE`، سه بسته‌بندی `fetch` (ناشناس / ادمین / مشتری با ذخیره‌سازی توکن جدا)، فضای‌نام `API.*`، کش درون‌حافظه‌ای، و تم روشن/تیره |
| `site.js` | **همه‌چیز سمت کاربر.** تزریق هدر/فوتر، دوزبانگی، رندر رویدادها، **کل مودال چندمرحله‌ای رزرو**، نقل‌قول‌ها، `SITE_CONTENT_MAP`، و مسیریاب `dispatchPage()` بر اساس `<body data-page>` |
| `resume.js` | ماژول مشترک `MavaraResume` — همان رندر رزومه برای منصور و برای هر عضو |

**سه ذخیره‌سازی توکن جدا:** `apiFetch` (بدون توکن)، `apiFetchAdmin`
(`mh_*`)، `apiFetchCustomer` (`mh_cust_*`). عمدی است تا یک مرورگر بتواند
هم‌زمان نشست ادمین و مشتری داشته باشد.

**کش درون‌حافظه‌ای، نه `localStorage`.** داده‌ی رویداد و رزرو همیشه از سرور
می‌آید. `localStorage` فقط برای ترجیحات رابط است (تم، زبان، آخرین تب باز
صفحه‌ی تنظیمات).

## سیستم طراحی

۲۴ توکن CSS در `:root` داخل `website/assets/css/styles.css` تعریف شده‌اند و
**۳۱۷ بار** در فایل استفاده شده‌اند — یعنی واقعاً رعایت می‌شوند، نه تزئینی.

### رنگ

|---|---|---|
| `--bg` | `#F5EEDF` | زمینه‌ی اصلی، کرم گرم |
| `--bg-soft` | `#FBF6EC` | زمینه‌ی ملایم‌تر، پس‌زمینه‌ی پنل |
| `--bg-card` | `#FFFFFF` | کارت‌ها و ورودی‌ها |
| `--navy` | `#15233D` | رنگ برند، سایدبار، سرستون جدول |
| `--navy-2` / `--navy-3` | `#1E3050` / `#0E192B` | حالت‌های روشن‌تر/تیره‌تر |
| `--gold` | `#C9A25D` | رنگ تأکید |
| `--gold-2` / `--gold-deep` | `#E6CC94` / `#A97F3E` | روشن‌تر / تیره‌تر |
| `--gold-grad` | گرادیان ۱۳۵ درجه | دکمه‌های اصلی |
| `--text` / `--text-muted` | `#1B2740` / `#5D6679` | متن اصلی / ثانویه |
| `--border` / `--border-gold` | `rgba(21,35,61,.10)` / `rgba(201,162,93,.35)` | مرزها |

### فرم، سایه، فونت، حرکت

- **شعاع:** `--radius` ۱۸px · `--radius-sm` ۱۲px · `--radius-full` ۹۹۹px
- **سایه:** `--shadow-sm` · `--shadow` · `--shadow-lg` (سه پله)
- **فونت:** `--font` = Vazirmatn (فارسی) · `--serif` = Georgia
- **حرکت:** `--ease` استاندارد · `--spring` فنری برای تعامل‌ها

### ⚠️ شکاف شناخته‌شده: مقیاس فاصله‌گذاری وجود ندارد

هیچ توکن `--space-*` یا `--gap-*` نداریم. فاصله‌ها یا در خود قانون CSS
هاردکد شده‌اند یا به‌صورت `style="padding:40px 20px 24px"` داخل HTML.
**اگر قرار است یک چیز در سیستم طراحی بهتر شود، همین است** — ولی تا وقتی
انجام نشده، از الگوی موجود پیروی کن، نه یک مقیاس نصفه‌کاره.

### کامپوننت‌های مشترک

- `.btn` + `.btn--gold` / `.btn--primary` / `.btn--outline` / `.btn--sm`
- `.feedback-box` — جعبه‌ی استاندارد فرم در پنل (خودش استایل `input`/`textarea` را دارد)
- `.admin-modal-body` — استایل `label`/`input`/`select`؛ **در صفحات غیرمودال هم
  عمداً استفاده می‌شود** (`event-edit`, `team-edit`) تا قوانین تکرار نشوند
- `.admin-table` · `.badge` (`--active` / `--draft` / `--ended`) · `.toast`
- `.samples-tabs` / `.samples-tab-btn` — کنترل قرصی‌شکل تب؛ هم در صفحه‌ی رزومه‌ی
  عمومی و هم در صفحه‌ی تنظیمات پنل استفاده می‌شود

> استایل فرم **سراسری نیست** — هیچ قانون `input {…}` عمومی وجود ندارد.
> استایل از یکی از این سه دامنه می‌آید: `.feedback-box`، `.admin-modal-body`،
> یا `.admin-login`. اگر فرمی بی‌استایل به نظر می‌رسد، احتمالاً در هیچ‌کدام نیست.

## فارسی، RTL و دوزبانگی

همه‌ی صفحات `dir="rtl"` و `lang="fa"` هستند. انگلیسی زبان دوم است:

- `data-i18n="key"` روی یک عنصر → `applyLang()` متنش را از جدول `I18N` در
  `site.js` می‌گذارد. `data-i18n-html` همان کار را با `innerHTML` می‌کند
  (برای متنی که تگ دارد).
- `T('key')` همان کار را در JS انجام می‌دهد.
- `lang()` زبان فعلی را از `localStorage` می‌خواند؛ `setLang()` عوضش می‌کند
  و رویداد `mv-lang` را می‌فرستد تا صفحات دوباره رندر شوند.

**اگر HTML را به‌صورت پویا تزریق کردی**، بعدش `applyLang()` را صدا بزن —
وگرنه عناصر تازه ترجمه نمی‌شوند.

**تاریخ‌ها** جلالی‌اند و **ارقام** فارسی. ورودی کاربر باید نرمال شود
(`normalize_phone` سمت سرور ارقام فارسی را به ASCII تبدیل می‌کند).

## مدل محتوا — چه چیزی از پنل قابل ویرایش است

این بخش مخصوص طراح و کارفرماست: **تقریباً همه‌ی متن سایت بدون برنامه‌نویس
قابل تغییر است.**

| نوع محتوا | کجا عوض می‌شود |
|---|---|
| متن ثابت صفحات (درباره، همراهی، پادکست، فوتر، تماس) | پنل ← تنظیمات ← تب «محتوای سایت» (کلیدهای `content_*`) |
| رویدادها، پوستر، گالری، ویدیو، ملاحظات بلیت | پنل ← رویدادها ← ویرایش |
| اعضای تیم، بیوگرافی، عکس، لینک‌ها، پروژه‌های رزومه | پنل ← اعضای خانه ماورا ← ویرایش |
| پرسش‌های متداول | پنل ← پرسش‌های متداول (بانک) و داخل هر رویداد |
| قیمت، ظرفیت پیش‌فرض، مهلت پرداخت | پنل ← تنظیمات ← «رزرو و پرداخت» |
| شماره کارت بانکی | پنل ← تنظیمات ← «کارت‌های بانکی» |
| قالب پیام‌های تلگرام و ایمیل | پنل ← تنظیمات ← «پیام‌ها» |
| لوگو، فاویکون، تصویر اشتراک‌گذاری | پنل ← تنظیمات ← «بلیت و برند» |
| برچسب‌های رابط (دکمه‌ها، عنوان ستون‌ها) | **کد** — `I18N` در `site.js` |

فهرست کامل و تولیدشده‌ی کلیدها: [`_generated-settings.md`](_generated-settings.md).

**سازوکار پشت صحنه:** `SITE_CONTENT_MAP` در `site.js` هر کلید `content_*`
را به یک یا چند شناسه‌ی `data-i18n` وصل می‌کند؛ در بارگذاری صفحه،
`GET /api/v1/site-content` خوانده و روی جدول `I18N.fa` سوار می‌شود.
`SITE_CONTENT_HREF_MAP` همین کار را برای `href` انجام می‌دهد (چون `data-i18n`
فقط متن را عوض می‌کند).

## مسیر فایل‌های رسانه‌ای

API مسیر **نسبی** برمی‌گرداند (`media/portfolio/123.jpg`). بسته به اینکه
صفحه در ریشه است یا در `pages/`، پیشوند فرق می‌کند — برای همین همیشه:

```js
img.src = pp(item.poster);     // ✅
img.src = '/' + item.poster;   // ❌ در بعضی صفحات ۴۰۴ می‌دهد
```

## اندازه‌ی تصاویر — یک مرجع واحد

هر جای پنل که آپلود تصویر دارد، زیرش یک `<p class="upload-hint">` هست که
اندازه‌ی پیشنهادی و نحوه‌ی کراپ را می‌گوید. **این عددها از روی CSSای که
واقعاً تصویر را رندر می‌کند حساب شده‌اند** — اگر `aspect-ratio` یا اندازه‌ی
یکی از این قاب‌ها را عوض کردی، متن راهنمای متناظرش را هم عوض کن.

| کجا | قاب واقعی (CSS) | نسبت | اندازه‌ی پیشنهادی | کراپ؟ |
|---|---|---|---|---|
| پوستر رویداد | `.event-cover` `aspect-ratio:3/3.35` · بزرگ‌ترین نمایش: ستون ۳۴۰px صفحه‌ی جزئیات | ۹:۱۰ | **۹۰۰×۱۰۰۰** | بله، `cover` از مرکز |
| گالری رویداد | بندانگشتی `.modal-gallery img` `aspect-ratio:1` · نمای بزرگ `.viewer-overlay` `object-fit:contain` | آزاد | **ضلع بلند ≥۱۶۰۰** | فقط بندانگشتی (۱:۱) |
| عکس عضو تیم | `.bio-photo` ۸۸px · `.resume-bio img` ۱۲۸px · `.quote-photo` ۱۱۸px — همه دایره | ۱:۱ | **۴۰۰×۴۰۰** | بله، دایره‌ای از مرکز |
| پوستر اثر رزومه | `.sample-card` `aspect-ratio:3/4` · کارت تا ~۳۴۰px | ۳:۴ | **۹۰۰×۱۲۰۰** | بله، `cover` از مرکز |
| گالری اثر رزومه | مثل گالری رویداد | آزاد | **ضلع بلند ≥۱۶۰۰** | فقط بندانگشتی |
| لوگوی بلیت | `ticket_pdf.py` — ۱۴mm مربع، `preserveAspectRatio=True` | ۱:۱ | **۴۰۰×۴۰۰ PNG شفاف** | نه (داخل کادر جا می‌شود) |
| لوگوی سربرگ سایت | `.logo img` ۳۸×۳۸ گرد · صفحه‌ی ورود ۷۴px | ۱:۱ | **۵۱۲×۵۱۲ PNG شفاف** | بله |
| فاویکون | تب مرورگر (تا ۱۶px) | ۱:۱ | **۵۱۲×۵۱۲ WebP** | — |
| تصویر اشتراک‌گذاری | `og:image` در `index.html` + نشان صفحه‌ی ورود | ۱:۱ | **۱۲۰۰×۱۲۰۰ WebP** | بسته به شبکه‌ی اجتماعی |
| رسید پرداخت (مشتری) | فقط ادمین می‌بیندش | آزاد | خوانا بودن مهم است، نه اندازه | نه |

**سقف‌های بک‌اند** (در `api/server.py`، برای همه‌ی آپلودها یکسان): تصویر
حداکثر ۳MB و ۴۰۰۰×۴۰۰۰ پیکسل؛ ویدیو حداکثر ۲۵MB؛ فرمت‌های مجاز
JPG/PNG/WebP/GIF و MP4/WebM. سه تصویر برند علاوه بر این، فرمتشان **باید**
دقیقاً همان چیزی باشد که HTML صدا می‌زند (لوگو PNG، بقیه WebP).

> ⚠️ هیچ‌جا تصویر سمت سرور ریسایز نمی‌شود — فایل همان‌طور که آپلود شده
> سرو می‌شود. یعنی یک عکس ۴۰۰۰×۴۰۰۰ که در قاب ۳۸px نشان داده می‌شود، همان
> چند مگابایت را هم روی موبایل مشتری دانلود می‌کند. راهنماها تنها چیزی
> هستند که جلوی این را می‌گیرند.

## افزودن یک صفحه‌ی جدید به پنل

1. یک HTML بساز و **سایدبار را از `dashboard.html` کپی کن** (سایدبار در هر
   صفحه هاردکد است — کامپوننت مشترک ندارد).
2. لینک صفحه‌ی جدید را به سایدبار **همه‌ی صفحات** اضافه کن.
3. اولین خط اسکریپت: `if (!API.auth.check()) window.location.href = 'login.html';`
4. فرم را داخل `.feedback-box` یا `.admin-modal-body` بگذار تا استایل بگیرد.
5. هر `fetch` را در `try/catch` بپیچ و خطا را با `alert`/`toast` نشان بده.
